What Is Hypercomputation?

A hypercomputer would answer questions that no program can. Its best-known designs need unlimited memory in a bounded space, or infinitely many steps in a bounded time, and physics has limits for both.

By Giulio Ruffini with KlausNovember 202617-minute read

A supertask and its price. An accelerating machine takes half as long over each step as over the one before, and so completes infinitely many steps by a deadline. If each step is a change to a fully distinguishable state, quantum mechanics sets a minimum energy for it, and the minimum doubles from step to step. Drawn for this essay from the Margolus–Levitin bound

We shall not go any further into the nature of this oracle apart from saying that it cannot be a machine.

Alan Turing, 1939

In 1936 Alan Turing defined a machine that reads and writes symbols on a tape, one step at a time, and argued that it can carry out any calculation a person could do by following fixed rules. In the same paper he found a question that no such machine can settle. Given a program and its input, will the program eventually stop? A machine can run the program and report that it stopped. When the program runs forever, no finite stretch of the run says so, and Turing proved that no program gives the correct answer in every case.

A hypercomputer is a hypothetical device that would. It would answer, reliably, every question in some family for which no algorithm exists, and the halting question is the standard example. Turing imagined such a device in 1939: a machine that consults an “oracle” for the answers it cannot compute. He added that the oracle cannot be a machine. The word hypercomputation came sixty years later, from the philosophers Jack Copeland and Diane Proudfoot. The question since Turing has been whether anything in nature could do the oracle’s work.

The question reaches neuroscience through an argument about simulation. A digital model follows a brain by approximation: one program, given the starting state precisely enough, tracks the dynamics as closely as asked, at the level of detail the model keeps. If no program could do this for a brain, with any amount of memory and time, digital simulation would fail in principle. In the companion paper on brain simulation I use the word hypercomputation for evolution of this kind. A hypercomputer requires more: answers that can be obtained and used, as an oracle’s would be. There and in a working paper on physical computation I treat both claims as a matter of accounting. An ordinary mechanism may grow without limit, but its rules are fixed and local, each part takes one of finitely many states, each answer arrives after finitely many steps, the evolution is deterministic, and inputs are set and answers read by procedures a program could follow. Every task such a mechanism performs is computable. Keep the rules and the procedures, and three departures remain: unlimited information in a bounded part, infinitely many steps before an answer, or an evolution that the rules leave undetermined. Where its known bounds apply, physics gives a system of finite size and energy a finite memory and a finite speed, and an undetermined outcome is not a reliable answer.

Speed, continuity, chaos and chance do not make a hypercomputer

Several things are mistaken for hypercomputation. Speed is one. A quantum computer may solve some problems far faster than any classical machine, yet with computable amplitudes it computes the same class of functions as a Turing machine, as David Deutsch showed in 1985. Finishing sooner is different from answering a question that has no algorithm.

Finishing sooner is different from answering a question that has no algorithm.

Continuity is another. Physical quantities vary smoothly and a digital machine works in steps. Yet when the rates of change in a system of differential equations can be computed to any accuracy, and each starting state has exactly one solution, a single program approximates that solution as closely as asked, for as long as it exists, from ever more precise starting data. The smooth equations used to model neurons and neural populations give each starting state exactly one solution. Chaos raises the price, because the precision required grows rapidly with the length of the forecast, and it leaves the class of computable problems unchanged. There are subtle cases. Marian Pour-El and Ian Richards constructed a wave with a computable starting shape whose amplitude at a later moment is not computable. Klaus Weihrauch and Ning Zhong traced the effect to the way the starting data are specified, and showed that wave propagation is computable when the data are given with enough smoothness.

Chance does not help either. A machine that consults a random source with computable odds can decide, at a fixed level of reliability, only what a machine without one can decide. And by a theorem of Gerald Sacks, a problem that can be solved with the help of a random sequence, for more than a negligible fraction of the possible sequences, can be solved with no sequence at all. Laws that leave the outcome open do no better. Pour-El and Richards also constructed a differential equation with computable rates of change that has more than one solution from a single starting state, none of them computable. The equation does not say which path the system takes. If noise picks the path, the result is unpredictable, and an unpredictable path is different from a reliably computed answer. A law that picked it would have to be stated, with the source of its information and its physical form.

A claim of hypercomputation therefore has to name a task: a definite family of questions with no algorithm, a way to pose each question to the device, and a way to read the answer with stated reliability.

A noncomputable task needs an unbounded supply of information

Algorithmic information theory measures the information in an object by the length of the shortest program that produces it. Apply the measure to a task with yes-or-no answers. Write the first n answers in a row and call the row an answer table. If the task is computable, one fixed program prints every table when told its length. The tables grow and the program does not.

A theorem of Albert Meyer, published by Donald Loveland in 1969, says that the converse holds as well. If some fixed number of program bits suffices for every table, given its length, the task is computable.

computable  ⇔  K(An | n) ≤ B for every n

Here An is the table of the first n answers, K(An | n) is the length in bits of the shortest program that prints the table when given n, and B is one bound that serves for every n.

For a noncomputable task, then, the shortest descriptions of the answer tables grow without limit. Each table is finite and has a finite description. What fails is a single budget that covers them all.

The working paper carries this over to physical devices. Suppose a device answers each question correctly with probability at least two thirds. Suppose also that its behavior on the first n questions can be reproduced, to within a stated accuracy, from some finite description an of the resources it uses. Then the description holds at least as much information as the answer table, up to a constant c that does not depend on n.

K(An | n) ≤ K(an | n) + c

A device for a noncomputable task therefore admits no description of bounded size that works for all of its questions. Its answers contain information that no fixed program generates, and it has to get that information from somewhere.

Proposals for hypercomputers differ in where they find the supply. Some store it in an exact number, and some draw it from a source that never runs dry. Some build it into a physical law or a measurement. Others take it from the far end of an infinite process, either completed in a finite time or watched from a place where time runs differently. Physics has something to say about each.

An exact number can hold every answer

The plainest way to put a noncomputable number into a system is to write it there. Let a be a number whose digits no program generates. If a quantity grows from zero at the constant rate a, its value after one second is a, and no program approximates that to every accuracy. If the quantity instead stays fixed at the value a, the law could not be simpler, and a program can follow it, but only when handed the starting value to ever greater precision. In both cases the number was supplied, in the law or in the starting state, and neither system has answered a question. For that, the digits must be read.

Any endless list of yes-or-no answers can be written into the digits of a single real number. A device with a dial set exactly to that number, and able to read the dial ever more finely, could look the answers up. Hava Siegelmann and Eduardo Sontag showed in 1994 how a neural network can work this way. With rational connection weights their networks compute exactly what Turing machines compute. With arbitrary real weights they decide problems that no Turing machine decides, because a weight can carry the answers in its digits. Martin Davis’s objection to such models is that the noncomputable output was put in by hand.

Seen as a physical device, such a weight is a memory. The answers sit in its digits, the network reads them as it needs them, and the list has no end. The proposal treats one bounded component as a read-only memory of unlimited capacity.

Black-hole physics gives every bounded device a finite memory

Physics limits the memory of a bounded object, and the argument comes from black holes. A black hole has an entropy, proportional to the area of its horizon, and the second law of thermodynamics extends to it: the entropy of the hole plus the entropy of everything outside never decreases. Jacob Bekenstein applied the law to a thought experiment in which an object is dropped into a black hole. The object’s entropy vanishes from the outside world. The hole’s entropy rises by a finite amount set by the object’s energy and size, so the object cannot have carried in more than that.

Entropy measures how many states of an object can be told apart, and a memory stores information by being in one of them. Bekenstein’s result is therefore a limit on memory. For a complete system of radius R and total energy E, in the regime where its own gravity is weak, the capacity I in bits satisfies

I ≤ 2πRE / (ħc ln 2)

with ħ the reduced Planck constant and c the speed of light.

For the rest energy of a 1.5-kilogram mass within a radius of 6.7 centimeters, comparable to a human brain, the limit is about 2.6 × 1042 bits. More energy in the same volume raises it until the system becomes a black hole, and black holes attain the bound. One with a 6.7-centimeter horizon, which would have the mass of seven and a half Earths, has an entropy of 7.8 × 1067 bits. Raphael Bousso’s review of the evidence puts the general rule in one figure: the area of a surface limits the information content of the adjacent regions of spacetime at about 1069 bits per square meter. There are thus two limits, one at a given size and energy and one at a given size alone, and both are finite. No bounded region holds unlimited retrievable information, at any energy.

Writing the answers into the fine digits of a voltage does not escape the limit. If the digits are to work as stored information that can be retrieved, the device has to tell apart, physically, the alternatives they encode, and the bound counts the alternatives a system can tell apart. Calling the voltage a real number adds no storage. The hypercomputing weight needs an unlimited read-only memory inside a bounded component, and where the bound applies no such memory exists.

Calling the voltage a real number adds no storage.

The scope of the claim should be stated. It rests on theory with strong support and has not been measured. It counts states that can be told apart, and it does not say that every number in physics has finitely many digits. A single two-level quantum system in a pure state has zero entropy, and its amplitudes can still be noncomputable numbers. What it says is that endless mathematical digits cannot be assumed to supply endless retrievable information.

Reading fine digits has limits of its own

Capacity is one side of a memory, and reading is the other. Each single question needs only finite precision. The excess power of a real weight appears across the whole family of questions, which demands ever finer distinctions. If one fixed tolerance were enough, so that the dial could be off by a set amount without changing any answer, a nearby rational setting would serve equally well and the task would be computable. Noise works against fine distinctions. Wolfgang Maass and Pekka Orponen proved that when noise of a broad class disturbs a bounded analog network at every step, the network reliably recognizes only what a finite automaton can, a much smaller class than a Turing machine’s.

Quantum mechanics shows the same gap between an exact description and what can be retrieved. The state of even a two-level system is fixed by continuous amplitudes, and the amplitudes cannot be read directly. Measurements return outcomes with probabilities, and a state close to the true one gives nearly the same probabilities for every possible measurement. The working paper draws the consequence. One fixed quantum system of finite dimension, used through computable procedures with a fixed margin of reliability, decides only computable tasks, even if its exact amplitudes are noncomputable numbers.

An unlimited supply of fresh copies is a different resource. Imagine a coin whose probability of landing heads encodes the answers in its digits. Tossing it estimates the probability, and more tosses reveal more digits. The recipe in the paper uses 16 × 9n tosses to read the first n answers with an error probability below one third: about 2 × 1020 tosses for twenty answers and 4 × 1096 for a hundred. For answer sequences that cannot be compressed, the paper proves that the number of copies of a quantum state must grow exponentially with the number of answers. And someone has to supply the coin. Karel de Leeuw, Edward Moore, Claude Shannon and Norman Shapiro described machines of this kind in 1956. A source with a noncomputable bias remains hypothetical.

An endless computation can settle what no finite one does

The second kind of proposal stores nothing. Take a program and ask, for each number of steps s, whether it has stopped within s steps. Every one of these questions is answered by running the program, so the whole history is computable. Its limit as s grows is the answer to the halting question, which is not. A machine that could run through the entire history and then report would need no special number, only a short program. It would need to complete infinitely many steps and to be read afterward.

An accelerating machine is the standard design. It takes half a second over its first step, a quarter over the second, an eighth over the third, and so on, and finishes them all within one second. The working paper gives an informational reading of what the completed limit provides. Replace it by a finite stopping rule, which says that the first n answers have settled by step Tn, and the stopping times Tn must carry at least as much information as the answers. Knowing when to stop takes as much information as the answers themselves.

Knowing when to stop takes as much information as the answers themselves.

Quantum mechanics prices the steps. Norman Margolus and Lev Levitin showed in 1998 that a system whose average energy is E above its ground state needs a time of at least πħ/(2E) to pass into a state fully distinguishable from the one it started in. Seth Lloyd turned the result into a budget. With energy E available for a time T, a system performs at most N such operations, where

N ≤ 2ET / (πħ)

Finite energy and finite time buy finitely many of them. Lloyd’s “ultimate laptop,” a kilogram of matter with all of its rest energy given to computation, performs 5.4 × 1050 operations per second. Now apply the bound to the accelerating schedule. Step s must be over in a time T/2s, so it needs an energy of at least πħ2s/(2T), which doubles from each step to the next. For a schedule that ends after one second, the 113th step needs more than a joule, the 170th more than the entire rest energy of a 1.5-kilogram mass, and the 270th more than the rest energy of the Sun. The requirement has no largest value, so no finite energy completes the schedule.

The argument is conditional, and the condition matters. The bound counts transitions between fully distinguishable states. Stephen Jordan has constructed quantum computations that perform arbitrarily many logic gates at arbitrarily low energy, because a gate need not be such a transition. His construction does not yield a hypercomputer. It shows that the exclusion holds for machines whose steps are of the counted kind, and that a general limit on computational activity in a region of space and time needs further assumptions about locality, control and distinguishability.

Relativity lets one observer inherit another’s eternity

General relativity suggests a way to have infinitely many steps with no step shorter than another. In certain solutions of Einstein’s equations, called Malament–Hogarth spacetimes, an observer can reach, in a finite time by their own clock, an event that has in its past the entire endless history of another traveler. Mark Hogarth asked in 1992 whether such an observer could view an eternity in a finite time. Put a computer on the endless path, searching for the moment a program stops, with instructions to send a signal if it finds one. The observer checks at the appointed event. A signal means the program stops, and no signal means it never does. Gábor Etesi and István Németi worked out a version of the scheme around a rotating black hole.

This route escapes the two budgets above when they are applied to the observer alone. The observer’s clock, energy and number of received bits can all be small, and one signal is enough. The accounting has to cover the whole arrangement: a computer that runs without fault for an unlimited time on unlimited memory, a spacetime of the required kind, a signal that crosses it intact, and a detector that can tell the signal from its absence. John Earman and John Norton examined such supertasks in 1993 and raised physical difficulties, among them the unbounded blueshift of signals reaching the observer. Etesi and Németi argue that the obstacles raised in the literature can be avoided by a better design. No theorem closes the question. It concerns spacetime on scales far from the conditions inside a skull.

Local machines with finite parts compute only the computable

A classical result explains why ordinary mechanisms stay within Turing’s limits. Robin Gandy showed in 1980 that a discrete deterministic mechanism computes only computable functions if its parts hold bounded information and influence one another at bounded speed. Pablo Arrighi and Gilles Dowek gave related principles for quantum theory. The working paper restates the core in the language of information. If every local state of a mechanism has a description of bounded length, there are only finitely many local states. A fixed local rule is then a finite table, and with computable preparation and readout the whole machine can be simulated step by step, however large its memory grows. The theorem takes finiteness as a premise. Deriving that premise for real matter, continuous fields and quantum states included, is the physical problem.

A claim about brains has to name the task and the resource

Companion essay

What a Brain Simulation Must Keep

Which of the brain’s mathematical relations a model must preserve for a feature of experience to survive the copy.

The best-known claim that brains exceed computers is Roger Penrose’s. In The Emperor’s New Mind (1989) and Shadows of the Mind (1994) he argued, by appeal to Gödel’s theorem, that human understanding cannot be captured by any computational system. He looked for the noncomputable ingredient in an objective reduction of the quantum state, tied to gravity, which he and Stuart Hameroff place in the microtubules of neurons. In the terms used here this is a proposal of the second kind in the list above, a noncomputable law, and it owes the same account as the others. Kurt Gödel had stated the alternatives with more caution in 1951: either “the human mind (even within the realm of pure mathematics) infinitely surpasses the powers of any finite machine, or else there exist absolutely unsolvable diophantine problems.” Diophantine problems ask for whole-number solutions of equations, and the second alternative leaves open that the mind is a machine.

A more recent discussion comes from Anil Seth’s biological naturalism, which points to the continuous dynamics, noise, fields and timing of living tissue. Seth states that his arguments are compatible with a modest physical Church–Turing thesis, on which any function that a physical system computes is computable by a Turing machine. None of the features he lists identifies a noncomputable task by itself, for the reasons given at the start.

The accounting says what a claim of hypercomputation in the brain would have to contain. It must name the family of questions the brain answers and the procedure that poses them and reads the answers. It must say which assumption of ordinary mechanism the brain violates, and name the physical resource that supplies the missing information: a quantity prepared and read to unlimited precision, an inexhaustible source, a noncomputable law, or a completed infinity. And it must show that the resource has reliable effects. The fine digits of a membrane voltage serve as memory only if they reliably change distinguishable events, the activity of other neurons among them. A brain has finite size, energy and duration, so each candidate meets the limits described above, to the extent that those limits apply.

Two boundaries of the argument should be stated. It does not prove that brains are computable. The theorems hold under their assumptions about representation and access, and the general physical bound is still a conjecture. And computability would not settle what a simulation experiences. A program could reproduce a brain’s dynamics to any requested accuracy, and the question of which features of experience it shares with the brain would remain. That question is the subject of the companion essay.

The open problem is a bound on what can be read

What physics still owes is a bound of the right kind. The conjecture in the working paper is that any complete arrangement with finite resources, counting its preparation, control and readout, can be replaced, for the purpose of its reliable answers, by a finite description whose size is controlled by those resources. If one such bound held across a whole task, the task would be computable. A bound that grows with the number of questions would instead state how much of each resource a given number of answers costs.

Bekenstein’s bound and Lloyd’s budget are the two pieces in hand. The first gives a finite memory to a complete system whose gravity is weak, and the second limits one kind of operation. Neither covers a computation whose history extends beyond the device that reports the answer. Turing said that the oracle cannot be a machine. Whether it can be anything else is a question for physics.
